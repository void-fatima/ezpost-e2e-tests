# کیس‌های مرحلهٔ احراز هویت واقعی و بازگشت به خرید EZPost

تاریخ طراحی: ۱۷ نوامبر ۲۰۲۶. Workspace مستقل EZPost؛ branch این مرحله `test/authentication-flow` است. این سند فقط طراحی sliceهای همین مرحله را ثبت می‌کند. هیچ هویت تست، کانال OTP، endpoint ورود/verify، کد عمومی، session موفق یا سیاست سبد از روی حدس ساخته نشده است. ۳۰ ID اصلی M01، IDهای سفارش، هشت ID سبد و تمام traceability قبلی بدون تغییر باقی می‌مانند.

**آخرین steering کاربر:** کاربر شمارهٔ تحت کنترل خود و دریافت SMS برای همان شماره را مجاز کرد و خواست شماره/OTP را مستقیماً در Cypress وارد کند؛ سپس صریحاً گفت **«موجودبودن حساب را تأیید نمی‌کنم».** نبود شماره یا کانال SMS blocker نیست؛ وجود حساب ordinary موجود و قابل تأیید هنوز فراهم نیست. چون ساخت حساب جدید بدون مجوز صریح، هویت اختصاصی و reset خارج دامنه است و UI ورود/ثبت‌نام مشترک دارد، **هیچ auth POST اجازهٔ عبور از guard به server نداشت و هیچ setup احراز هویت تکمیل نشد**. دو تلاش UI برای OTP-start پس از پایان تست‌ها توسط guard مسدود شدند؛ جزئیات E4 پایین ثبت است. setup احرازشده و post-login assertions هر دو صفرند. مسیر دستی آینده MANUAL-ASSISTED خواهد بود و فقط post-checkهای واقعی آن می‌توانند automated نتیجه داشته باشند.

**checkpoint اجرای فعلی:** هفت native test موجود و دو desktop account-link test تازه در هر دو Chrome و Firefox نمایان اجرا شدند: **۹PASS در هر مرورگر، صفرFAIL/pending/skipped/not-run**؛ همگی public/no-submit و بدون ordinary session. هر دو مرورگر روی source ID مشترک `57c400d6aacd060fdf37e83107e30fdeb0382993c6a3acd1615dc4af00a292bd` اجرا شدند. این PASSها ورود واقعی یا تکمیل AUTH-04/AUTH-07 نیستند.

در E4، تلاش‌های `POST /api/v1/auth/otp/start` در **UTC17:20:30.589 و17:20:31.902**، پس از پایان تست‌ها در **17:19:31.830** ثبت شده‌اند. هر دو به خطای `M01 forbids application mutation` رسیدند و `state:Errored/hasResponse:false` دارند. این‌ها test جدید، challenge موفق یا manual-assisted authenticated setup نیستند. نتیجهٔ ۱۸PASS خودکار تغییری نکرد؛ آخرین runner Firefox همچنان۲PASS وstopped/visible بود. خالی‌بودن فرم در assertionهای زمان اجرای تست ثبت شده بود؛ **فرم فعلی دیگر خالی ادعا نمی‌شود**. هیچ مقدار واردشده یا body خوانده/ذخیره نشده است.

## استفادهٔ مجدد از پوشش مستقل موجود

## معیار correctness، اجرای بعدی و privacy

پیش از هر code change، case مربوط باید precondition واقعی، action، نتیجهٔ observable، منبع انتظار و رفتار غلطِ قابل رد بالا را به assertion مشخص تبدیل کند. هویت ordinary باید از مرجع خصوصی supplied و observable contract واقعی بیاید؛ `user !== null`، HTTP200، toast، completed-request یا URL به‌تنهایی موفقیت نیستند. پاسخ mock احراز هویت، فقط UI simulation است و هرگز backend/login PASS محسوب نمی‌شود.

روش manual sign-in برای شمارهٔ تعیین‌شده مجاز شده، اما به‌علت K1 **هیچ setup احراز هویت دستی تکمیل نشد و automation اجازهٔ start/verify ندارد**. دو تلاش UI مسدودشدهٔ E4 جدا ثبت‌اند؛ نبود مقدار تایپ‌شده یا نبود تلاش ادعا نمی‌شود. پس از رفع K1، setup آینده با برچسب MANUAL-ASSISTED ثبت می‌شود؛ تنها post-checkهای واقعاً اجراشده automated محسوب می‌شوند. شمار کنونی automated login و authenticated manual setup هر دو صفر است؛ caseهای BLOCKED به passed یا skipped-completed تبدیل نمی‌شوند. هیچ phone/OTP در fixture، command log، screenshot یا public artifact نگهداری نمی‌شود؛ correlation آینده فقط در حافظهٔ خصوصی و بدون چاپ مقدار است.

guard موجود suiteهای قبلی محفوظ است. slice عمومی فعلی support/config جدا دارد و همان guard بدون تغییر را استفاده می‌کند؛ هیچ auth POST مجاز نیست. slice واقعی آینده پس از رفع K1، فقط requestهای دقیق و ضروریِ کشف‌شده را می‌تواند مجاز کند. هیچ broad exception suppression، conditional حذف assertion اصلی، forced click، arbitrary sleep، timeout حدسی، auth state injection یا account/session شخصی پذیرفته نیست. هر negative attempt به budget و fixture معلوم محدود می‌شود.

اجرای همین subset عمومی در Cypress محلی `open → E2E → Chrome` سپس Firefox، با source hash ثابت بالا انجام و application-opened/spec-loaded/tests-completed جدا در E3 ثبت شد: **۱۸PASS live read-only،۰controlled،۰authenticated manual setup،۰post-login assertion**. هیچ test failure یا rerun مرورگری رخ نداد؛ دو خطای guard پس از completion در E4 جزو test outcomeها نیستند. تمام expectationهای native قبلی حفظ شدند. phone، OTP، raw auth response، cookie/token/session dump، browser profile و screenshot هویت‌دار در PUBLIC منتشر نمی‌شوند؛ artifacts عمومی پیش از stage بررسی می‌شوند. P10 همچنان باز است و این batch رفع آن یا تکمیل سفارش/پرداخت را ادعا نمی‌کند.
